# AI Poster — Админ-панель

Веб-интерфейс для управления AI-публикациями в Telegram: команды, каналы, источники контента, генерация через LLM, задачи и трейсинг.

## Концепция

AI Poster работает в режиме **team-first** (аналогично DigitalOcean или Vercel). Переключение между командами происходит через дропдаун в шапке, и весь интерфейс (сайдбар, дашборд, данные) автоматически отражает контекст текущей команды. `teamId` **не в URL** — хранится в `TeamContext` (персистируется в `localStorage`).

## Как это работает — руководство пользователя

### Общий принцип

AI Poster автоматизирует ведение Telegram-каналов. Вы подключаете **источники контента** (RSS-ленты, Telegram-каналы, веб-сайты), система собирает из них материалы, пропускает через **LLM**  для переработки под ваш стиль, и публикует готовые посты в ваши **Telegram-каналы** — по расписанию или мгновенно.

```
Источники → Сбор материалов → Обработка LLM → Публикация в Telegram
```

### Начало работы

1. **Регистрация** — создайте аккаунт на странице `/register` (или примите приглашение по ссылке)
2. **Создание команды** — при первом входе система предложит создать команду (или вас пригласят в существующую)
3. **Добавление канала** — подключите свой Telegram-канал, дайте боту права на публикацию
4. **Добавление источников** — укажите, откуда брать контент (RSS, Telegram-каналы, сайты)
5. **Настройка стиля** — опишите, как должны выглядеть посты (тон, формат, язык, хэштеги)
6. **Запуск** — система начнёт автоматически собирать контент и публиковать посты

### Источники контента

Три типа источников для сбора материалов:

| Тип | Что подключать | Пример |
|-----|---------------|--------|
| **RSS** | Любая RSS/Atom лента | `https://techcrunch.com/feed` |
| **Telegram** | Публичный TG-канал | `@ai_news_official` |
| **Веб-сайт** | Любой сайт (парсинг через AI-агента) | `https://news.ycombinator.com` |

При добавлении источника система проверяет доступность, показывает превью контента и позволяет убедиться, что всё настроено правильно. Для веб-сайтов запускается AI-агент, который автоматически определяет структуру страниц.

### Каналы публикации

Каждый Telegram-канал настраивается индивидуально:

- **Режим публикации**: мгновенный (сразу после генерации) или по расписанию (cron)
- **Стиль постов**: текстовое описание желаемого стиля — тон, формат, аудитория, использование эмодзи и хэштегов
- **Привязка источников**: один канал может получать контент из нескольких источников, и наоборот
- **Тестирование**: можно сгенерировать ��естовый пост без реальной публикации, чтобы проверить стиль

### Команды и роли

Вся работа организована по **командам**. Вы можете состоять в нескольких командах одновременно и переключаться между ними через дропдаун в шапке.

- **Владелец (owner)** — полный доступ: управление каналами, источниками, участниками, настройками команды
- **Участник (member)** — всё то же самое, кроме управления участниками и опасных операций (удаление команды)

Владелец приглашает участников по email — им приходит ссылка для принятия приглашения.

### Рекламные кампании

Модуль рекламы позволяет массово рассылать посты по нескольким каналам:

1. **Создание рекламного поста** — отправьте сообщение Telegram-боту `@ai_poster_bot` и ответьте на него командой `/ads`
2. **Создание кампании** — выберите пост, укажите каналы для рассылки, настройте время отправки
3. **Отслеживание** — следите за статусом рассылки, просмотрами и ошибками по каждому каналу

> Для работы с рекламой необходимо привязать Telegram-аккаунт в профиле.

### Мониторинг и аналитика

- **Дашборд** — сводка по команде: активные каналы, источники, последние задачи
- **Задачи (Jobs)** — журнал всех операций системы с детальными логами
- **LLM-трейсы** — полная информация о каждом вызове LLM: промпт, ответ, токены, стоимость
- **Публикации** — все опубликованные посты с поиском и фильтрами
- **Контент** — все собранные материалы из источников

### Теги и организация

Каналы и источники можно помечать **цветными тегами** для удобной организации и фильтрации. Теги создаются и управляются через кнопку «Управление тегами» на страницах каналов �� источников. Фильтрация по тегам работает по принципу «любой из выбранных» (OR-логика).

## Модель доступа

Система имеет **два раздельных потока авторизации**:

### Глобальные админы (`/admin/*`)
- Вход по **нику + пароль** на `/admin/login`
- Отдельная сущность от обычных пользователей
- `root`-админ создаётся при старте, **не может быть удалён или деактивирован**
- Управляют пользователями, командами, приглашениями и LLM-аналитикой

### Обычные пользователи
- Вход по **email + пароль** на `/login`
- Две роли в команде: **owner** и **member**
- Owner приглашает member'ов по email; member'ы принимают через `/invite/:token`
- Флаг `canCreateTeam` и лимит `maxTeams` устанавливаются админом

## Быстрый старт

1. Перейти на `/login`
2. Ввести: `john@example.com` / `password`
3. Откроется дашборд команды **Tech News Team**
4. Переключить команду через дропдаун в шапке

Доступ администратора:
1. Перейти на `/admin/login`
2. Ввести: `root` / `admin`

```
── Публичные ──

/register             → Регистрация
/forgot-password      → Восстановление пароля
/invite/:token        → Принятие приглашения в команду
/onboarding           → Первичная настройка (создание команды)

/admin/teams          → Все команды

/admin/llm-analytics  → Аналитика использования LLM
/admin/llm-traces/:id → Детали LLM-трейса

── Команда (требует авторизации) ──
/                     → Дашборд команды
/channels             → Список каналов
/channels/:id         → Детали канала (стиль постов, привязанные источники, история публикаций)
/sources              → Список источников
/sources/:id          → Детали источника (лента контента, опубликованные посты)
/posts                → Опубликованные посты (поиск, фильтры)
/posts/:id            → Детали поста (метаданные, связанные канал/источник/задача)
/items                → Весь собранный контент
/items/:id            → Детали контент-элемента
/jobs                 → Список задач (фильтры по типу/периоду/каналу/источнику)
/jobs/:id             → Детали задачи (логи, связанный пост, LLM-трейсы)
/llm-traces           → Список LLM-трейсов
/llm-traces/:id       → Детали LLM-трейса (промпт, ответ, токены, стоимость)
/members              → Участники команды (приглашение по email)
/settings             → Настройки команды (имя, лимиты, удаление)
/ads                  → Рекламные кампании
/ads/posts            → Рекламные посты (захваченные через бота)
/ads/:id              → Детали кампании
/profile              → Профиль пользователя (имя, email, таймзона, привязка Telegram)
```

## Архитектура UI

### Лейаут

- **Шапка**: логотип, дропдаун переключения команды, пользовательское меню
- **Сайдбар** (`RootLayout.tsx`): три группы навигации, разделённые `border-gray-100` с `my-2`:
  1. Обзор, Каналы, Источники, Кампании
  2. Публикации, Контент, Задачи, LLM Трейсы
  3. Участники, Настройки
- **Админ-лейаут** (`AdminLayout.tsx`): отдельный сайдбар для маршрутов `/admin/*`
- **Тосты**: `<Toaster>` из `sonner` смонтирован глобально в `RootLayout.tsx` — все уведомления через `toast()`, без `alert()`

### Дизайн-паттерны

- **Без внешних Card-обёрток** на страницах-списков — каждый элемент отдельная карточка
- **Фильтры по статусу/типу**: кнопки-переключатели с каунтерами (напр., фильтр статуса на ��транице каналов)
- **Фильтры источник/канал**: `Select`-дропдауны (напр., на странице задач)
- **Фильтр по периоду**: общий компонент `PeriodPicker` (`/src/app/components/PeriodPicker.tsx`) с пресетами (сегодня, неделя, месяц) и кнопкой сброса, работает с объектами `DateRange`
- **Просмотровые страницы** (Контент, Задачи, LLM-трейсы, Посты): формат `divide-y` с карточками-превью
- **Пагинация**: общий компонент `Pagination` с размером страницы

### Специфические решения

- **Страница задач**: без фильтра-переключателя по статусам — только дропдауны для типа задачи, периода, канала и источника с общей кнопкой сброса
- **Задачи**: нет прогресс-бара; статус `running` показывает синий бейдж «Выполняется»
- **Страница постов**: строка поиска вместо кнопок-переключателей по статусу
- **Детали поста**: секция метаданных с кликабельными бейджами источника и канала (переход на `/sources/:id` и `/channels/:id`)
- **Лимиты команды** (страница настроек), порядок: Постов в день (100) → Запуски агента парсера (20) → Источников (20) → Каналов (10) → Участников
- **Страница профиля**: селектор таймзоны (24 зоны) через Select-дропдаун, сохраняется в `localStorage`
- **Удаление команды**: разрешено только если нет каналов, нет источников и нет участников кроме владельца

```

  ↓ fetch job
```
